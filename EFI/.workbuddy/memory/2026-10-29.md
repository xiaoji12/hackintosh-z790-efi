## 关键结论（已实证，含一次重要纠错）
1. **【纠错】IO80211Family 和 IOSkywalkFamily 在 Tahoe 中是存在的**。
   `strings BootKernelExtensions.kc | grep com.apple.iokit.IO80211Family` 有命中（3 处），
   磁盘上 `/System/Library/Extensions/IO80211Family.kext`（CFBundleVersion 1200.13.1，无代码包装，
   代码在内核集合）、`IOSkywalkFamily.kext`（1.0）都在。
   ⚠️ 早期用 `kmutil showfileset` 搜不到是因为该命令未加权限输出为空，由此得出"框架被移除"是**错的**。
2. **WiFi 真正的失败原因**：config 的 `Kernel > Block` 里有
   `com.apple.iokit.IOSkywalkFamily`（MinKernel 24.0.0）。AirportItlwm 的 OSBundleLibraries 明确依赖
   `com.apple.iokit.IOSkywalkFamily` 和 `com.apple.iokit.IO80211Family`，依赖被 Block → **kext 无法加载**。
   叠加旧 EFI 里的 AirportItlwm 2.4.0 不是 Tahoe 构建，两重原因。
3. **蓝牙硬件本身可见**：USBInjectAll（无端口映射）下 XHCI 枚举出全部 24 口（HS01-14 + SS01-10），
   USB 树中有 idVendor 32903 / idProduct 38 = 8087:0026。此前"搜不到蓝牙"是 UTBMap 把 HS12-14 砍掉所致。
4. 该 config 有与原始 EFI 相同的错配：Cpuid1Data 伪造成 Skylake-X（0x0A0655）、DummyPowerManagement=true、
   UpdateSMBIOSMode=Custom（导致处理器 Unknown）。

## 硬件监控（温度/功耗/频率）— 2026-10-29 18:42

**根因：iStat Menus / Stats 读不到，不是软件问题，是机型映射**
- 用 ctypes 直连 AppleSMC 枚举全部 **126 个键**，实测本机（VirtualSMC 1.3.8 + MacPro7,1）暴露：
  - `TC0P`/`TC0D`/`TC0H` = CPU 封装/晶片/散热器温度（实测 38~47°C，随负载变化，**准确**）
  - `TC0C`~`TC9C` = 10 个核心温度（12600KF 是 6P+4E=10 核，完全吻合）
  - `F1Ac` = 风扇转速 fpe2（实测 ~700 RPM）；`F2Ac`~`F6Ac` 返回 0（未接风扇，需过滤）
  - **`PCAM` 是假数据**：空闲 103.8W、满载 0.0W，纯乱跳 → VirtualSMC 伪造，不可用
  - `CLKT`=75485(ui32)、`CLWK`=0xffff → **频率键无效**，读不到频率
- iStat/Stats 按机型 MacPro7,1 去查 Mac Pro 的键（TCAP/TCAH 等），与 VirtualSMC 提供的标准 DTS 键不匹配 → 全空

**解决方案：自建监控（~/Applications/SystemMonitor/）**
- `monitor.py`：ctypes 直连 SMC + HTTP 服务（端口 8765）+ 内嵌深色网页面板
- `smcperf_daemon.py`：root 常驻，跑 `powermetrics --samplers cpu_power -i 1000` 流式解析，
  把功耗/频率写 `/tmp/.smcperf.json`（chmod 644）；面板读该文件，**不需要调用方有 sudo**
- `/Library/LaunchDaemons/com.local.smcperf.plist`：RunAtLoad + KeepAlive，开机自启
- `启动监控.command`：双击启动面板（会先 pkill 旧实例）
- 实测：温度 47°C / 功耗 31.1W / 频率 2699MHz / 风扇 705RPM 全部正常

**关键环境限制（别再踩）**
- 本机 WorkBuddy 会话的**整个进程树禁止执行 sudo**（`/usr/bin/sudo: Operation not permitted`，
  即使沙箱外、即使 osascript 以用户身份也不行）→ 验证必须走"root 守护进程 + 文件交换"这种间接路径
- `/usr/local/bin` 无法创建（EACCES），root 也不行 → daemon 脚本只能放用户目录
- `/etc/sudoers.d/powermetrics` 已写入 NOPASSWD 白名单（visudo -c 通过）作为备用方案，但无法在本环境验证
- `screencapture` 报 "could not create image from display"，无法截图自查界面
